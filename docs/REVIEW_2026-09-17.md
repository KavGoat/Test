# MarkForge review — 2026-09-17

This review used Qt pointer and keyboard events, saved PDFs inspected with MuPDF,
and 1280×860 renders of the live window. The full suite result is in
`COMPLETED_TASKS.md`. The actual Bluebeam Windows application was unavailable
on this Mac. The comparison below uses Bluebeam's published [Properties Toolbar
guide](https://support.bluebeam.com/revu/features/edit-markups-properties-toolbar.html),
[markup customization guide](https://support.bluebeam.com/online-help/revu20/Content/RevuHelp/Tutorials/Customizing-Markups.htm),
[tools reference](https://support.bluebeam.com/online-help/revu20/Content/RevuHelp/Menus/Tools/Tools-Menu.htm),
and [calibration guide](https://support.bluebeam.com/online-help/revu20/Content/RevuHelp/Menus/Tools/Measure/Calibrate--MV.htm).

## Findings repaired in this review

| Area | Finding | Change and evidence |
| --- | --- | --- |
| PDF output | A blank page carried a full-page white painted rectangle, so a viewer's snapshot could pick it up. | Print/export now omits viewing paper. The PDF alpha regression checks an untouched pixel is transparent. |
| Save | A failed write could damage the destination; pruning an image asset also broke Undo. | Save writes a temporary PDF then atomically replaces the destination, retaining Undo assets in memory and retaining unframed pending assets. The existing `test_file_lifecycle.py` cases now pass. |
| Export | Image writing could silently fail or let a title change the output path. | Output names are sanitized and a failed image write raises an error shown in the window. |
| Contents links | Save did not write the links, and export relied on rows having been painted first. | Links are computed from the contents item and embedded in both Save and Export. A PDF reader checks both outputs. |
| Calibration | The preview used measurement ticks and dimension artwork. | The in-progress guide draws one cosmetic dashed line, then disappears when the scale is set. |
| PDF snapping | Ordinary Open kept the source vectors out of the scene, leaving Snap to Content without targets. | Vector snap geometry is loaded on first use, kept outside document markups, and queried through page-local bins. The September 18 follow-up removed the old import cap and materializes only vectors near the pointer; real pointer tests check endpoints, intersections and re-editing an endpoint. |
| Alignment | The previous draft point could catch the next point; dashed guides could leave fragments. | The current draft is excluded from snap targets, and the full old/new guide strips are repainted. Pointer-event and paint-region tests check second-point placement and guide removal. |
| Curve preview | Shape bounds used vertices and omitted outward bows. | Bounds include the full painted path; a live handle-drag regression checks this. |
| Synchronization | Each window needed a separate Sync choice; peer scrollbar updates could echo an old zoom during shared-scene resizing. | One choice propagates to all views of the same document, new views inherit it, and zoom updates are guarded until the source anchor is settled. Multi-window tests cover Page and Document sync. |
| Properties panel | Selecting a markup could squash groups until fields overlapped and became unreadable. | The scroll area's content layout now retains its minimum height. The visual regression checks all groups are full-height and do not overlap. |
| Style controls | Opacity used sliders in Properties, arrow ends had text-only choices, and important text controls were absent from the top bar. | Editable spin boxes with step buttons, graphical line-end/style/hatch previews, text colour/font/weight/alignment, and snapshot/image border controls are exposed where relevant. |
| Count and imported drawing | Count number/text styling was incomplete in Properties; an imported drawing offered line/fill controls that cannot alter its per-stroke artwork. | Count now exposes its number and shared font styling in Properties and the style toolbar. Imported drawings offer only effective overall opacity. |
| Stamp and flag | The stamp's font was missing from the style toolbar and its corner radius was inaccessible; flags offered dash/hatch options they do not paint. | Stamp font controls and corner radius are reachable. Flag controls now match its solid painted symbol. |
| Break symbol | Size and position were fixed. | Independent width, height and position controls and three distinct drag handles edit the symbol; serialization also reads the prior size/position format. |
| Pages | Add Page created one page with inherited paper size. | The new dialog chooses quantity and paper size, adding them in one undo step. |
| Window sizing | The long status message could contribute to a wide minimum window. | It can now yield width; a visual regression checks a 1280-pixel window. A Windows 1920-pixel run remains necessary. |

The shipped tools cover drawing, notes, contents, measurement and takeoff.
Names checked against Bluebeam's tools reference include Arrow, Callout,
Cloud+, Dimension, Center radius and Calibrate. The Style toolbar is dynamic by
item type, like Bluebeam's Properties Toolbar. A selected text box is still
wide at 1280 pixels: its last controls are in toolbar overflow. This needs a
layout pass if every control must stay visible at that width.

## Remaining validation and requirements

- The Whiteout request was clarified on September 18: remove flattened PDF
  artwork in the selected region and retain live editable markups. The focused
  regression checks the source drawing, live markup, save, Undo and Redo.
  The previously requested “fit” option was withdrawn; page count and paper
  size remain selectable.
- The saved links were checked with MuPDF; a click in Bluebeam and another PDF
  viewer is still an acceptance check.
- The Windows geometry warning, graphics-driver behavior, and the user's dense
  PDFs require testing on the affected Windows machine.
- Cold extraction of snap vectors on a very dense PDF can still delay its
  first snap event. Profile that document before claiming a speed improvement.
- A broad audit of every specialized item's metadata and editing controls is
  still open. This pass checked common appearance controls and the selected
  rectangle/text/arrow screenshots, but did not visually inspect every dialog,
  tool, tab and panel in Bluebeam itself.
